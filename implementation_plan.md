## 2. Data

* **SciFig-Controlled** (`data/benchmark`, `docs/BENCHMARK.md`): 400 synthetic matplotlib figures
  (200 2D, 200 3D), 282 train / 118 test, exact gold elements, entities, links and geometry.
  Molecular figures use **16 real PDB structures** (`data/raw/pdb/SOURCES.md`), split by structure.
  Generator seed 42, matplotlib 3.11.2.
* **demo/dataset**: four synthetic placeholders for the UI (relabelled; previously presented as
  SciCap). `alphafold_t1087_3d.json` is a synthetic helix (relabelled; previously attributed to
  AlphaFold).
* **Real SciCap / arXiv / AlphaFold DB / RCSB**: not reachable from the build environment.

Answers to the Phase-4 data questions: the repository contained no real SciCap data and no real
3D geometry; the real SciCap is graph plots only. No public dataset pairing paper figures with
their underlying 3D geometry and grounding labels is known to us, so the pairing was constructed
by rendering real PDB structures.

### 3.2 Grounding (Phase 3) — `pipelines/evaluate_gnn.py` → `results/gnn_grounding_results.json`

Mean ± std over seeds 42/43/44. Train time = once per model; inference = per figure, median.

| Setting | Method | Precision | Recall | F1 | Acc@1 | MRR | Train (s) | Inference (ms) |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| oracle elements | A rules | 0.261 | 0.834 | 0.397 | 0.339 | 0.465 | 0 | 0.10 |
| oracle elements | B GNN | 0.998 | 0.994 | 0.996 ± 0.002 | 0.998 | 0.999 | 4.4 | 3.4 |
| oracle elements | no message passing | 0.997 | 0.984 | 0.990 ± 0.003 | 0.996 | 0.998 | 2.4 | 2.8 |
| OCR elements | A rules | 0.260 | 0.715 | 0.381 | 0.320 | 0.428 | 0 | 0.08 |
| OCR elements | B GNN | 0.962 | 0.855 | 0.905 ± 0.003 | 0.896 | 0.898 | 4.3 | 4.1 |
| OCR elements | no message passing | 0.968 | 0.858 | 0.910 ± 0.002 | 0.897 | 0.899 | 2.6 | 2.8 |
| held-out entity names (oracle) | A rules | 0.275 | 0.866 | 0.418 | 0.298 | – | 0 | – |
| held-out entity names (oracle) | B GNN | 0.940 | 0.748 | 0.833 ± 0.013 | 0.837 | – | – | – |
| held-out entity names (oracle) | no message passing | 0.950 | 0.764 | 0.846 ± 0.025 | 0.878 | – | – | – |

Held-out-names experiment: 12 entities never linked in training (82 test links, 112 training figures).

**Findings.**
1. The learned grounder is far better than the rules on this benchmark (F1 0.38 → 0.91 end to end).
   The rules over-link: precision 0.26, because LEGEND→every METHOD and AXIS→every METRIC/VARIABLE
   also hit the distractor entities.
2. **Message passing contributes nothing measurable**: the identical model with message passing
   disabled is equal within noise in every setting. The gain comes from the supervised pairwise
   classifier and its lexical features (acronym match, abbreviation defined in the paragraph,
   trigram similarity, type compatibility). Claiming the improvement for the GNN *as a graph model*
   is not supported.
3. Oracle-element F1 ≈ 0.99 shows the benchmark's grounding task is close to saturated when the
   vocabulary is shared; the held-out-names split (F1 0.83) is the more informative number.
4. Latency: rules 0.1 ms; GNN 3–4 ms inference per figure (dominated by graph construction);
   training 4 s on CPU. The previously reported 1,747.85 ms mixed per-figure re-training into
   "latency"; it is not an inference time.

### 3.3 3D-figure detection (Phase 4) — `pipelines/evaluate_phase4.py` → `results/phase4_results.json`

| Detector | is-3D acc. | is-3D P | is-3D R | 7-way type acc. | Train | Inference |
|---|---:|---:|---:|---:|---:|---:|
| CNN on pixels (128×128) | 1.000 | 1.000 | 1.000 | 1.000 | 12.3 s, 25 epochs | 0.59 ms / figure (batched) |
| Text keywords (caption + paragraph) | 1.000 | 1.000 | 1.000 | – | – | – |

Both are saturated on this benchmark: the text result is an artefact of template text, and the
CNN result shows only that matplotlib 2D vs 3D renders are separable in-domain. The CNN classifies
the flat-ellipse placeholder `demo/dataset/samples/scicap_003.png` as 2D (correct for that image;
the old filename rule called it 3D).

Engineering note: the first CNN run's eval-mode accuracy varied strongly between seeds (validation
71% vs 100% with identical weights in train mode) because BatchNorm running statistics were
miscalibrated. All BatchNorm models are now recalibrated on the full training set after training
("precise BN"); validation accuracy is 1.00 for seeds 42/43/44.

### 3.4 Figure ↔ 3D geometry alignment (Phase 4) — same script

63 test 3D figures (25 protein views of 5 unseen structures, 18 surfaces, 20 3D scatters) query a
gallery of 43 unique test geometries. Rotation augmentation was **off**, selected on a
structure-disjoint validation split (val MRR 0.611 vs 0.453 with augmentation).

| Geometry encoder | R@1 | R@5 | MRR | Protein R@1 | Surface R@1 | Scatter3D R@1 |
|---|---:|---:|---:|---:|---:|---:|
| chance | 0.023 | – | – | – | – | – |
| untrained (pointnet+multiview) | 0.016 | 0.079 | 0.086 | 0.00 | 0.06 | 0.00 |
| PointNet | **0.222** | 0.508 | **0.364** | 0.32 | 0.22 | 0.10 |
| Multi-view | 0.191 | 0.556 | 0.353 | 0.32 | 0.06 | 0.15 |
| PointNet + multi-view (sum) | 0.159 | **0.603** | 0.351 | 0.20 | 0.17 | 0.10 |

Training: 60 epochs, Adam lr 1e-3, wd 1e-4, batch 32, multi-positive InfoNCE, 205.6 s
(137 figures, 93 geometries). Inference: image encoder 0.44 ms / figure, PointNet 7.5 ms /
geometry, multi-view CNN 0.69 ms / geometry (rendering excluded).

Alignment is clearly above chance and above the untrained baseline, including for unseen
protein structures, but far from reliable (R@1 ≈ 0.2).

SCQ components (B): entity coverage 0.561, technical correctness 0.528, reconstruction fidelity
0.334, retrieval accuracy 0.880.

**Answer to the Phase-4 research question** (*does explicit 3D representation add value beyond
text + 2D + GNN?*): on this benchmark, **not for grounding or text→figure retrieval** — D and E
differ from B by less than one seed-std in grounding F1 and by ≤ 0.006 MRR in retrieval (118
queries, no significance test; treat as no effect). The 3D branch's value is a **new capability**:
retrieving the figure that depicts a given 3D structure (geometry→figure R@1 0.14, chance ≈ 0.02),
which no 2D/text configuration can do.

## 4. Reproduction

```bash
python -m src.data.benchmark_generator --out data/benchmark --seed 42
python pipelines/evaluate_phase4.py        # ~4-15 min CPU
python pipelines/evaluate_gnn.py           # ~10 min CPU incl. OCR on first run (~14 min)
python pipelines/run_ablation.py           # ~15 min CPU
python -m pytest tests/                    # 34 tests (1 skipped without checkpoints)
```

Seeds: generator 42; models 42 (+43, 44 for grounding); validation splits use fixed RNG seeds
(0, 1, 7) inside the scripts. CPU results are not bit-for-bit reproducible across thread counts;
grounding F1 varied by ≤ 0.002 between 2- and 4-thread runs.

## 6. Limitations

* All quantitative results are on a synthetic, single-style benchmark with template text; they do
  not establish performance on real scientific papers.
* Grounding uses gold entities (oracle NER); the regex NER does not cover the benchmark vocabulary.
* No pretrained vision or language models could be downloaded: no CLIP, no Sentence-Transformers,
  no SciBERT, no NLI. Retrieval uses TF-IDF; verification is lexical.
* 16 real structures; 118 test figures; retrieval/SCQ are single-seed without confidence intervals.
* The 3D image-side embedding is learned from 137 training figures; alignment is weak (R@1 ≈ 0.2).
* The OCR layout heuristics are tuned to matplotlib layouts.

## 7. Blockers

* **CLIP / Sentence-Transformers / SciBERT / NLI weights**: huggingface.co unreachable.
* **Real benchmark data** (SciCap, arXiv, RCSB, AlphaFold DB): hosts unreachable.
